Secure User Login System: Hash Table in C

CHash tablesLinked listsmalloc / freeFile I/OAuthentication
Overview
A user registration and login system written in C. Accounts are stored in an 11-bucket hash table, and the program can register users, update passwords, check a login, and load existing accounts from a text file.
My role
Implemented the full hash table module (hash_table.c): initialising the table, the hash function, look-up, registration, password checking, loading from file and freeing memory. I tested it through a command-line program that loads the users, registers a user and checks a password.
Challenges & solutions
  • Two user IDs can land in the same bucket (for example 4, 15 and 26 all map to bucket 4) → used separate chaining, so each bucket holds a linked list and new users are added at the front.
  • Bad input could crash the program → every function checks for NULL pointers, negative IDs and passwords longer than 40 characters, and the file loader stops cleanly on malformed lines.
  • Memory leaks with dynamic allocation → free_buckets walks every chain and frees each node before resetting the bucket.
Security reflection
Passwords are currently stored in plain text. In a real system I would store a salted hash (for example bcrypt or Argon2), so that a leaked user file wouldn't reveal anyone's password. That's directly relevant to the authentication topics in Security+.
From my code: finding a user in its bucket
User *find_user(const HashTable *ht, int user_id)
{
    if (ht == NULL || user_id < 0)
        return NULL;

    int table = get_bucket_for_user(user_id);  // user_id % 11
    User *pointer = ht->buckets[table];

    while (pointer != NULL)                    // walk the chain
    {
        if (pointer->user_id == user_id)
            return pointer;
        pointer = pointer->next;
    }
    return NULL;
}
